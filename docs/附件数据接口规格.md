# 附件数据接口规格

本文件说明 OPIMS **实际读取**各附件的哪些位置。用途只有一个：
**修订细则附件模板时对照本表**，避免模板定稿后系统读不出来。

> 谁该看：改附件模板的人（中心）、改解析代码的人（我或另一个模型）。
> 每次附件模板变更，本文件必须同步更新，并在 `CHANGELOG.md` 记一笔。

状态：对应代码 `for-claude` 分支 `86fa62a`（2026-08-05）。

---

## 〇、通用规则

1. **文件名决定系统能否找到它**，命名不合规 = 系统认为「没交」。
   格式：`{项目简称}-{代码}-{周期}.{扩展名}`，周期是 6 位数字 `YYYYMM`（无横杠）。
   项目简称必须与「项目清单」里的 `short_name` **完全一致**。

2. **表头按文字定位，不写死行号**。在表头上方加说明行、加 logo、调整行高都不会影响解析——
   但**关键列的文字不能改**（改了就找不到）。

3. **列的顺序可以调整**，系统按列名找，不按位置找。

4. **多余的列会被忽略**，可以自由增列；但**删掉或改名下表中的列会导致解析失败或字段变空**。

5. 日期格式宽松（`2026-08-05`、`2026/8/5`、Excel 日期序列值都认），但**推荐统一 `YYYY-MM-DD`**。

6. **所有时限一律按日历日计算**，不扣周末与节假日（细则 5.1）。修订模板时不要引入「工作日」口径。

## 一、附件 B-1 月度进度数据表 → 「进度指标」页

| 项 | 值 |
|---|---|
| 文件名 | `{项目简称}-MPD-YYYYMM.xlsx` |
| 存放位置 | `{项目目录}/06.Report/Monthly Report/` |
| 读取方式 | Sheet「进度数据」按 **A 列标签 → B 列值** |

系统读取的 A 列标签（**文字必须完全一致**）：

| A 列标签 | 用途 | 备注 |
|---|---|---|
| `报告周期` | 显示 | |
| `数据日期` | 显示 | |
| `填报人` | 显示 | |
| `币种` | 显示 | |
| `关键路径滞后天数` | **风险灯判定**（细则 4.1） | 必须是整数，否则告警 |
| `付款里程碑预计滞后` | **风险灯判定** | 填「是」触发橙灯条件 |
| `本期已产生 LDs` | **风险灯判定** | 填「是」触发红灯；也认无空格的 `本期已产生LDs` |
| `本期计划产值` | 本期完成率 | |
| `本期实际产值` | 本期完成率 | |
| `累计计划产值` | **SPI 分母** | 为 0 或缺失时 SPI 不可用，届时风险灯**仅按滞后天数判定** |
| `累计实际产值` | **SPI 分子** | |
| `项目自评风险灯` | 与系统判定比对，不一致时标「自评不一致」 | 填 绿/黄/橙/红 |

**⚠️ SPI 由系统统一计算**（累计实际产值 ÷ 累计计划产值），**项目部不要填 SPI**。
各项目自己算口径不同就无法横向比较。B 列填「系统计算」四字的行会被自动跳过。

**修订模板时注意**：新增指标列可自由加；但上表 12 个标签是判灯与考核的输入，
改名前必须同步改 `backend/services/progress_data.go`。

## 三、附件 E 合同时效日历 → 「时限雷达」页

| 项 | 值 |
|---|---|
| 文件名 | `{项目简称}-TBC-YYYYMM.xlsx` |
| 存放位置 | `{项目目录}/05.Schedule/` 下（同 EOT 规则） |
| 读取方式 | 按表头定位，**表头行须同时含 `合同条款号` 和 `触发日期`** |

| 列名 | 用途 |
|---|---|
| `序号` | 显示 |
| `合同条款号` | **定位表头用** |
| `时效代码` | T1–T9，自动转大写 |
| `触发事件描述` | 显示为事项名 |
| `触发日期` | **定位表头用**，倒计时起算日 |
| `时限天数` | 日历日；到期日 = 触发日期 + 时限天数 |
| `实际完成日` | 有值即视为已办结，不再计紧急度 |
| `状态` | 填「已完成」同上 |
| `责任人` | 显示 |
| `备注` | 显示 |

### 与「中心登记簿」的关系（重要）

时限雷达有**两个数据源**：本附件 + 中心在系统里直接登记的条目。
两者按 `项目 | 时效代码 | 到期日` 去重合并，**同一条以中心登记簿为准**，
命中的标为「登记+附件E」。

**因此附件 E 的定位变了**：它不再是时效数据的唯一入口，而是项目部侧的补充。
中心在合同评审阶段登记的条目不依赖本附件，云盘读不到时雷达照常工作。

### 附件 G 第十节「缺失型信号」如何进系统

附件 G 第十节的 G10.1–G10.5 **没有独立的 Excel 模板**，走中心登记簿录入，
在「时限雷达 → 登记时效条款」里选「附件 G 信号」下拉即可。

**G10.5（我方视为认可期限届满）必须选「方向 = 我方风险」**——
系统据此在到期前强制提醒（默认 3 日，细则 6.3.2）并在同紧急度档内优先排序。
选错方向会让最危险的一类混进普通索赔机会里。

## 四、报送核查读什么

「月度报送 → 报送核查」不解析文件内容，**只看文件名是否存在、修改时间是否在应交期限内**。
应交清单见 `docs/OPIMS_操作说明.md` 第 12 章。

因此：**文件名不规范 = 缺交**，哪怕内容完全正确。这是最常见的「明明交了却显示缺交」的原因。

### 定这几个模板时，建议先想清楚三件事

1. **哪些字段是判定用的、哪些只是记录用的**——判定用的字段系统要读，
   记录用的可以自由发挥。上面每张表里标了「用途」的都是判定用。
2. **谁填、什么时候填**——中心填的走系统登记（像时限雷达那样），
   项目部按月报的走 Excel 附件。两条路的成本差别很大。
3. **能不能纯用日期算**——能纯算日期的（如「红灯亮起后 30 日无纠偏方案」）
   落地成本最低、漏报风险最高，应优先做（同附件 G 第十一节的判断）。
