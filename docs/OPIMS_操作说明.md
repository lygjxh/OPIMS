# OPIMS 海外项目综合管理系统 — 操作说明

> **首次使用请先看第 0 章**；项目部同事只需看第 0、12、13 章即可完成日常报送。

---

## 0. 快速开始

### 0.1 中心管理员：三步把系统跑起来

| 步骤 | 操作 | 说明 |
|:--:|---|---|
| 1 | 双击 `opims.exe` | 浏览器自动打开 `http://localhost:8080` |
| 2 | 「项目文件 → 设置根目录」 | 指向 `…\海外运营中心`（含 `01.Project Files`、`08.Policy` 的那一层，**不是** `01.Project Files` 本身） |
| 3 | 「项目清单 → 导入」 | 导入公司项目管理情况汇总表，系统仅导入**境外**项目 |

完成后各模块即可使用。**注意：报送核查、进度指标、时效预警、工期索赔只针对
「在建」状态的项目**——完工项目不会出现在这些页面，属正常设计。

### 0.2 项目部同事：每月要交什么

| 交什么 | 交到哪 | 截止 |
|---|---|:--:|
| 月度进度分析报告（附件 B） | `05…/06.Report/Monthly Report/` | 次月 5 日 |
| **月度进度数据表（附件 B-1）** | 同上 | 次月 5 日 |
| 月度管理问题及建议（六方面梳理） | 同上 | 当月 30 日 |
| 三月滚动计划 | `05.Schedule/` | 当月 25 日 |
| 合同时效日历（附件 E） | `05.Schedule/Time Bar/` | 次月 5 日 |
| 工期索赔跟踪台账（附件 D） | `05.Schedule/EOT/` | 次月 5 日 |
| 季度产值分解表 | `06.Report/Monthly Report/` | 季度末月 25 日 |
| 项目周报 | `06.Report/Weekly Report/` | 每周五 |

**文件名必须按第 12 章的规则命名**，否则系统认不出来，会算作「缺交」。

### 0.3 页面打不开或没数据？

先看第 14 章的排查表，多数是「根目录设错」或「文件命名不规范」，不是系统故障。

## 1. 系统启动

双击 `opims.exe` 即可启动。系统会在后台启动 Web 服务，并自动打开浏览器访问 `http://localhost:8080`。

- 如果系统已在运行，再次双击会直接打开浏览器，不会重复启动。
- 关闭方法：在命令行窗口中按 **Enter** 键。

> **注意**：`opims.exe` 必须与 `frontend-dist` 文件夹放在同一目录下，否则页面无法加载。

## 3. 数据存储与备份

### 3.1 数据库位置

所有数据存储在 `opims.exe` 同目录下的 `opims.db`（SQLite 单文件）。不要手动修改或删除此文件，否则数据会丢失。

### 3.2 备份

在项目清单页面（未来将在系统设置中提供）点击 **备份** 按钮，选择保存路径，系统将生成文件：

```
opims_backup_20260615_1730.db
```

命名规则：`opims_backup_年月日_时分.db`

### 3.3 恢复

点击 **恢复** 按钮，选择之前备份的 `.db` 文件，确认后系统会用备份覆盖当前数据。

> **警告**：恢复操作不可撤销，执行前请确认当前数据已备份。

## 4. 项目文件根目录 ⚠️ 重要

### 4.1 根目录指哪一层 ⚠️ 最容易设错的地方

**根目录 = `海外运营中心` 这一层**，即包含 `01.Project Files`、`06.Received File`、
`08.Policy` 等编号文件夹的那一级。

> **不是** `01.Project Files`，也**不是**某个具体项目的文件夹。

设错的后果：项目文件能看到，但**国别档案、收文归档、简称映射都会失效**。

<details><summary>为什么是这一层（历史说明）</summary>

早期版本的根目录确实指向 `01.Project Files`，因为当时系统只读项目文件。
后来新增了「国别档案」（读 `08.Policy`）和「收文归档」（读 `06.Received File`），
这两个目录与 `01.Project Files` 是**平级**的，根目录必须上移一层才能同时覆盖。

</details>

### 4.2 目录结构

```
海外运营中心/                          ← ★ 根目录设到这一层
├── 01.Project Files/                 ← 各项目文件夹（系统主要读写区）
│   ├── 尼日利亚PLF项目/                 文件夹名 = 项目简称，必须完全一致
│   │   ├── 01.Contract/                合同文件
│   │   ├── 02.Sub-contract/
│   │   ├── 03.Project Planning/
│   │   ├── 04.Quality/
│   │   ├── 05.Schedule/                进度计划 L1–L4、三月滚动计划
│   │   │   ├── Time Bar/               合同时效日历（附件 E）
│   │   │   └── EOT/                    工期索赔台账（附件 D）
│   │   ├── 06.Report/
│   │   │   ├── Monthly Report/         月报、进度数据表、六方面梳理、季度产值
│   │   │   └── Weekly Report/          周报
│   │   ├── 07.Time Sheet/
│   │   └── 09.Others/
│   └── 阿布扎比LNG项目/
│       └── ...
├── 06.Received File/                 ← 收文箱（收文归档的默认扫描目录）
│   └── 01.项目管理情况汇总表/            公司下发的汇总表与「海外项目简称.xlsx」
├── 07.Sub-contractor/
│   └── 01.Qualification Documents/   分包商资质文件
└── 08.Policy/                        ← 政策库（Obsidian vault 根）
    └── 出入境政策/                     国别档案的数据源
```

### 4.3 各模块分别读哪个目录

| 模块 | 读取位置 |
|---|---|
| 项目文件 / 报送核查 / 进度指标 / 工期索赔 / 时效预警 | `<根>/01.Project Files/<项目简称>/…` |
| 国别档案 | `<根>/08.Policy/出入境政策/` |
| 收文归档 | `<根>/06.Received File/`（可在页面上改为其它目录） |
| 分包商资质 | `<根>/07.Sub-contractor/01.Qualification Documents/` |
| 项目简称映射表 | `<根>/06.Received File/01.项目管理情况汇总表/海外项目简称.xlsx` |

### 4.4 关键规则

- **项目文件夹名必须与项目清单中的「项目简称」完全一致**——这是全系统的关联键
- 每个项目文件夹下应有 9 个编号子文件夹（即使为空）
- `05.Schedule/Time Bar/`、`05.Schedule/EOT/`、`06.Report/Monthly Report/`
  这三个子目录是后加的，**若某项目缺少，对应功能会显示「未建目录」**，
  可从 `0模板项目` 复制目录结构补齐

### 4.5 设置根目录

在「项目文件」页面点击 **设置根目录**，填入路径。系统会记住，下次启动无需重设。

**换电脑或移动云盘位置后**：只需重新设置根目录一处，所有模块自动跟随——
系统内不存在其它需要单独配置的路径。

## 5. 项目清单

### 5.1 数据导入

**导入源**：公司项目管理情况汇总表（`.xlsx` 格式）。

**导入规则**：
- 系统仅导入 **境外** 项目（境内项目自动过滤）。
- 项目简称和合同编号通过与汇总表同目录的 `海外项目简称.xlsx` 自动匹配（按项目名称匹配）。
- 不修改原始汇总表。

**冲突处理**（导入时项目中已存在同简称的项目）：

| 模式 | 行为 |
|---|---|
| 跳过（默认） | 保留现有数据，不导入冲突项 |
| 覆盖 | 用导入数据替换现有数据 |
| 保留两者 | 标记冲突，不做任何操作 |

**GPS 坐标**：汇总表中如有 GPS 列，支持以下格式自动解析：
- 逗号分隔：`25.2048, 55.2708`（纬度, 经度）
- 度分秒：`53°20′22.9″N 6°14′12.1″W`
- Plus Code（开放位置码）

### 5.2 列表筛选

默认只显示「在建」和「未开工」项目，在建排前。选择筛选条件后取消默认限制。

筛选维度：
- 项目类型：EPC / PC / C
- 项目状态：未开工 / 在建 / 停工 / 完工
- 境内/境外
- 国别（从数据中自动提取）
- 关键字：搜索项目简称、项目名称、合同编号

### 5.3 新建 / 编辑

点击 **新建** 按钮，或点击项目行 → **编辑**。填写的字段包括：

- 项目简称（必填，系统内唯一）
- 合同编号（必填，唯一）
- 项目名称（必填）
- 项目类型、项目状态、合同额
- 实施单位、境内/境外、国别
- GPS 坐标（可选，格式同上）

### 5.4 删除

删除为**软删除**——项目在列表中不可见，但数据库中的关联记录保留并标记为「已删除项目」。其它板块的历史数据不会丢失。

### 5.5 导出

点击 **导出** 按钮，将**当前筛选结果**导出为 `.xlsx` 文件。导出范围 = 你看到的内容。

## 6. 项目文件管理

### 6.1 查看文件

每个项目下的 9 个子文件夹以树形结构展示。点击文件会用系统默认程序打开。

### 6.2 刷新

点击 **刷新** 按钮，系统会重新扫描根目录下所有项目文件夹的最新状态。

### 6.3 文件变化的感知方式

系统**不做后台实时监控**。在系统外新增、修改、删除文件后，需点击「刷新」或
重新进入页面才会看到变化，以当前文件系统实际状态为准。

## 7. 合同文件 ⚠️ 关键规则

### 7.1 存放位置

合同文件必须放在对应项目文件夹的 `01.Contract` 子文件夹中。

### 7.2 命名规则

系统根据文件名自动识别合同类型：

| 文件名特征 | 显示标签 | 示例 |
|---|---|---|
| 包含 `contract`（不含 `supplement`） | **主合同** | `Main Contract.pdf`、`工程合同_v2.docx` |
| 包含 `supplement` | **补充合同** | `Supplement Agreement.pdf` |
| 包含 `supplement` + 末尾数字 | **补充合同一/二/三...** | `Supplement 2.pdf` → 补充合同二 |
| 都不包含 | **合同文件**（兜底） | `agreement.pdf` |

> **建议**：文件命名中包含 `contract` 或 `supplement`，以便系统正确分类。补充协议如需编号，在文件名末尾加数字（如 `Supplement 1.pdf`）。

### 7.3 查看合同

在项目清单页面，点击项目详情弹窗中「合同编号」旁的 **📄 合同文件** 按钮，系统会列出该项目 `01.Contract` 下的所有合同文件。点击文件名即可打开。

## 8. 分包商黑名单

### 8.1 功能说明

管理需要限制合作的分包商信息。

**字段**：
- 分包商简称（必填）、分包商名称（必填）
- 国别、提报项目（关联项目简称）
- 列入原因、列入日期（必填）、限制日期、列入提报人
- 拉出原因、拉出日期、拉出提报人

### 8.2 操作规则

- 新建记录后状态为「列入中」，可编辑、可删除。
- 所有操作（新建/编辑/拉出/删除）均记录到操作日志。
- **拉出锁定**：填写拉出信息后，记录状态变为「已拉出」，此后 **不可再修改、不可删除**。
- 删除仅限「列入中」状态的记录。

### 8.3 筛选

支持按国别、提报项目、状态（列入中 / 已拉出）筛选。

## 9. 首页看板

- **数字卡片**：项目总数 + 各状态（在建/未开工/停工/完工）分项计数，附占比。**点击卡片可跳转到项目清单并自动按该状态筛选**；数量为 0 的卡片淡化显示。
- **世界地图**：
  - 填写了 GPS 坐标的项目按真实位置标记（实线圈）。
  - 未填 GPS 但国别可识别的项目，按**国别近似定位**（虚线圈），地图下方会标注这类项目的数量。需要精确位置请补填 GPS 坐标。
  - 鼠标悬停显示项目简称、状态、国别。不同状态用颜色 + 形状区分（圆点/空心圈/方块/小圆点）。
- **合同额分布**：环形饼图，可切换**按地区／按国别**；可按状态筛选（全部 / 在建 / 未开工 / 完工，后三者可多选）。按地区时点击扇区或图例可下钻查看国别明细。
- **快捷入口**：卡片可跳转至各功能板块；待开发板块点击会提示「模块建设中」。

## 9A. 国别档案

展示各国出入境政策，数据来自云盘 `08.Policy\出入境政策\` 下的 Obsidian 笔记。

**使用方式**
- 卡片按风险等级（高→中→低）排序，显示签证类型、预计办理周期、更新日期
- 点击卡片打开完整档案：签证/办理/材料/费用/风险等十节内容
- 右上角「公司内部制度摘要」查看内部审批流程——**目标国政策与公司内部流程需叠加计算，才是真实的人员到岗周期**
- 超过 90 天未更新的档案会标黄提示核查（出入境政策变化快）

**维护方式**：在 Obsidian 里改笔记即可，系统实时读取，**不需要在 OPIMS 里重复录入**。
新增国别时若名称与 OPIMS 不一致（如「印度尼西亚」vs「印尼」），需联系开发方补映射。

**关联**：项目详情弹窗里的「国别」若该国有档案，会显示为可点击链接；
首页地图点击项目标记也可弹出该国政策摘要。

## 9B. 进度管理

五个子菜单，共用「在建项目」范围。点「进度管理」本身进入**总览页**，
五张卡片各显示一个子模块的当期关键数字，点卡片进入明细。

> 总览页的五组数字都要扫云盘目录，是并发取的，某一项取不到只影响那一张卡片。
> 卡片显示错误提示时，点进对应子页面能看到更具体的原因。

### 9B.1 指标（风险灯）

读取各项目附件 B-1，按《进度管理实施细则》4.1 自动判定风险灯：

| 灯 | 条件 | 系统提示的应对措施 |
|:-:|---|---|
| 🟢 绿 | 滞后 ≤3 天 **且** SPI ≥0.95 | 正常监控，周报记录 |
| 🟡 黄 | 滞后 3–7 天 **或** SPI 0.90–0.95 | 项目部内部讨论，10 日内出纠偏方案 |
| 🟠 橙 | 滞后 7–14 天 **或** SPI 0.85–0.90 **或** 付款里程碑预计滞后 | 出正式纠偏计划，报中心备案 |
| 🔴 红 | 滞后 >14 天 **或** SPI <0.85 **或** 已产生 LDs | 中心介入，组织专题分析会 |

- 取**最严重**的一项判定，页面会显示具体触发原因
- **SPI 由系统统一计算**（累计实际产值÷累计计划产值），项目部不填。各项目自己算口径不同，无法横向比较
- 项目自评灯与系统判定**不一致时会标出**，这类项目需重点核实

### 9B.2 报送核查

矩阵看板：行=项目，列=文件类型，格子显示已交/迟交/缺交。

- **点击任一格**可人工修正判定并加备注（如「已邮件收到，未归档」），修正会计入合规率，所有修改留痕
- **「存本期快照」**：把本期核查结果存档，作为年度考核依据。文件事后可能被删改，快照锁定核查当时的事实
- **「年度合规率」**：按快照统计各项目按时率，可导出 Excel。**只统计已存快照的周期**——没核查过的月份不算缺交
- 「待人工识别」列出**命名不合规**的文件。命名规范但属于其它周期的文件不会出现在这里

### 9B.3 工期索赔

读取各项目附件 D，跨项目汇总索赔状态。

- `CN 应发日 = 发现日 + 10 日历日`，`PCO 应交日 = CN 发出日 + 21 日历日`
- 到期未发/未交的**标红置顶**——逾期即丧失索赔权
- 按状态、按索赔类别分别汇总，可看「累计请求天数/金额」

## 9C. 合同时效预警 ⚠️ 最需要每天看的一页

菜单位置：**进度管理 → 合同时效预警**。

读取各项目附件 E，按**日历日**倒计时。

| 灯 | 剩余天数 |
|:-:|---|
| 🔴 红 | <7 天，或已逾期 |
| 🟡 黄 | 7–14 天 |
| 🟢 绿 | >14 天 |

- **最紧急的排最前**，已完成的沉底
- **时限一律按日历日算，不扣除周末与节假日**。各国假日不同，按工作日算易错；日历日得出的到期日更早，属安全方向
- 剩余天数每次打开实时重算，不缓存

> ⚠️ 《实施细则》5.1 明确：**违反时效将导致不可逆的索赔权丧失**。这页红灯必须当天处理。

## 9D. 收文归档

菜单位置：**进度管理 → 收文归档**。

把收到的文件自动改名并归入对应项目目录，省去手工重命名与搬运。

**操作步骤**
1. 把文件放进 `06.Received File\`（或在页面上指定其它目录）
2. 打开「收文归档」，系统列出待归档文件，并**尝试猜测**项目/类型/周期
3. 逐个确认或补选项目、类型、周期，点「归档」
4. 弹窗显示「将归档为 XXX」，确认后执行

**三条安全保障**
- **先复制并校验，确认成功后才删原件**，不会出现文件搬到一半丢失
- **目标已存在同名文件时不会覆盖**，而是提示改用新版本号（如 `-v2`），也可显式选择覆盖
- **每次操作可回滚**：点「操作记录」→「回滚」把文件搬回原处。若原位置已被新文件占用，系统会拒绝回滚，不会覆盖你新放的东西

**猜测规则**：已规范命名的文件三项全猜出；只含项目简称的只猜项目；完全认不出的留空由人工选择。**系统宁可让你多选一次，也不会猜错后静默归错位置。**

## 10. 常见问题

**Q：导入后项目简称显示为项目全名？**
A：请检查 `海外项目简称.xlsx` 是否存在于汇总表同目录下，且格式为：序号 / 项目简称 / 合同编号 / 项目名称（4列）。

**Q：合同文件按钮显示"未找到合同文件"？**
A：确认该项目文件夹下的 `01.Contract` 子文件夹中有文件，且项目简称与文件夹名一致。

**Q：文件根目录变了怎么处理？**
A：在「项目文件」页面点「设置根目录」，选择新位置后点击刷新。

**Q：项目删了能恢复吗？**
A：目前不支持界面恢复，数据仍在数据库中（标记为已删除）。如需恢复请联系管理员操作数据库。

**Q：某个项目的国别显示"其他"，怎么改？**
A：国别是**导入时**从项目名称/地址中自动识别的。显示"其他"说明名称里没有系统能识别的国名。两种处理方式：① 在项目清单中点「编辑」手动填写国别；② 若该国有多个项目，联系开发方在国别关键词表（`backend/services/country.go`）中补充该国名，然后**重新导入**——注意仅修改关键词表不会更新已入库的旧数据。

**Q：地图上项目位置不准？**
A：虚线圈表示"按国别近似定位"，落点是该国代表坐标（通常是首都或主要工程区），不是项目实际位置。要精确定位，请在项目详情中填写该项目的 GPS 坐标。

**Q：在文件夹里加了文件，系统里没看到？**
A：系统不做后台实时监控，请在「项目文件」页面点击「刷新」，或重新进入该页面。

## 12. 文件命名规则 ⚠️ 项目部必读

系统靠**文件名**识别文件属于哪个项目、哪类文件、哪个周期。命名不对，系统认不出来，
会算作「缺交」并列入「待人工识别」。

### 12.1 统一格式

```
{项目简称}-{类型代码}-{周期}[-v版本].{扩展名}
```

**示例**：`尼日利亚PLF项目-MPR-202607.pdf`

| 部分 | 规则 | 示例 |
|---|---|---|
| 项目简称 | **必须与 OPIMS 项目清单完全一致**，也与项目文件夹名一致 | `尼日利亚PLF项目` |
| 类型代码 | 见下表，大写字母 | `MPR` |
| 周期 | 月度 `YYYYMM`／季度 `YYYYQn`／周 `YYYYWnn` | `202607`、`2026Q3`、`2026W28` |
| 版本（可选） | 同期修订时加 `-v2`、`-v3`；**首版不加** | `-v2` |
| 扩展名 | 原文件扩展名 | `.pdf` `.xlsx` `.docx` `.mpp` |

> 同期存在多个版本时，系统取**版本号最大**的作为当期有效版本；旧版不会被当成
> 「命名不合规」，可放心保留。

### 12.2 类型代码对照表

| 代码 | 文件 | 周期 | 存放位置 |
|:--:|---|:--:|---|
| `MPR` | 月度进度分析报告 | 月 | `06.Report/Monthly Report/` |
| `MPD` | **月度进度数据表（附件 B-1）** | 月 | `06.Report/Monthly Report/` |
| `SIX` | 月度管理问题及建议（六方面梳理） | 月 | `06.Report/Monthly Report/` |
| `QOV` | 季度产值分解表 | 季 | `06.Report/Monthly Report/` |
| `WKR` | 项目周报 | 周 | `06.Report/Weekly Report/` |
| `RP3` | 三月滚动计划 | 月 | `05.Schedule/` |
| `TBC` | 合同时效日历（附件 E） | 月 | `05.Schedule/Time Bar/` |
| `EOT` | 工期索赔跟踪台账（附件 D） | 月 | `05.Schedule/EOT/` |

### 12.3 进度计划的命名（与上表不同）

进度计划按层级和版本命名，**不带周期**：

```
{项目简称}-{L1|L2|L3|L4}-v{版本号}.{扩展名}
```

**示例**：`尼日利亚PLF项目-L2-v3.mpp`

| 层级 | 含义 |
|:--:|---|
| L1 | 里程碑级计划 |
| L2 | 管理级计划 |
| L3 | 控制级计划 |
| L4 | 作业级计划 |

- 存放在 `05.Schedule/` 根目录
- **新版不删旧版**，系统自动取版本号最大者为当前有效版本
- 报送核查页的「进度计划」列会显示各层级当前版本，如 `L1 v1  L2 v3`

### 12.4 常见命名错误

| ❌ 错误写法 | 问题 | ✅ 正确写法 |
|---|---|---|
| `七月月报.pdf` | 缺项目简称与类型代码 | `尼日利亚PLF项目-MPR-202607.pdf` |
| `尼日利亚PLF-MPR-202607.pdf` | 简称与清单不一致（少了「项目」） | `尼日利亚PLF项目-MPR-202607.pdf` |
| `尼日利亚PLF项目-月报-202607.pdf` | 类型用了中文，须用代码 | `…-MPR-202607.pdf` |
| `尼日利亚PLF项目-MPR-2026-07.pdf` | 周期带了横杠 | `…-MPR-202607.pdf` |
| `尼日利亚PLF项目-MPR-202607-最终版.pdf` | 后缀不是版本号格式 | `…-MPR-202607-v2.pdf` |
| `LNG罐区计划2026.6.23.mpp` | 完全不符合规范 | `尼日利亚PLF项目-L2-v1.mpp` |

> **不想手工改名？** 用「收文归档」模块：把文件丢进 `06.Received File\`，
> 选好项目/类型/周期，系统自动改名并归位（见 9D 章）。

## 13. 数据填写规则 ⚠️ 项目部必读

需要系统读取内容的有三张 Excel：**附件 B-1、附件 D、附件 E**。
空白模板在云盘 `08.Policy` 同级的模板目录，或向中心索取。

### 13.1 三条通用规则

1. **只填原始事实，不填能算的。** 完成率、SPI、到期日、剩余天数、预警灯都由系统算，
   模板中标为「系统计算」的灰底格**不要填**。手填的剩余天数在报告写完的次日就失效了。
2. **一格一值，不要合并单元格、不要用下划线填空。** 数值必须落在单元格里。
3. **项目简称必须与 OPIMS 项目清单完全一致**，这是全系统的关联键。

### 13.2 数值与日期格式

| 项目 | ✅ 正确 | ❌ 错误 |
|---|---|---|
| 金额 | `1200000` | `1,200,000`、`120万`、`$1200000` |
| 天数 | `9`、`-3`（负数=提前） | `约10天`、`9-10天` |
| 日期 | `2026-07-31` | `2026.7.31`、`7月31日`、`26/7/31` |
| 是否类 | `是` / `否` | `Y`、`有`、`√` |
| 风险灯 | `绿` / `黄` / `橙` / `红` | `绿色`、`正常` |

> 模板里这些字段已做成下拉选项，**直接选不要手打**，可避免绝大多数错误。

### 13.3 附件 B-1（月度进度数据表）

共 13 个填报字段，正常 5 分钟填完。

**必填且最关键的三项**：

| 字段 | 说明 |
|---|---|
| **关键路径滞后天数** | 整数，正数=滞后、负数=提前。取自 P6/MS Project 关键路径当前完成日与基准完成日之差。**这是风险灯的主要输入** |
| **累计计划产值 / 累计实际产值** | 系统据此算 SPI。**填错会直接导致风险灯判错** |
| **付款里程碑预计滞后 / 已产生 LDs** | 这两项任一为「是」即触发橙灯/红灯，不填会让灯偏乐观 |

**易错点**：
- 累计产值填成了本期产值 → SPI 严重失真
- 累计计划产值填 0 或留空 → SPI 无法计算，风险灯只能依据滞后天数判定

### 13.4 附件 E（合同时效日历）

**只需填两个关键字段，其余由系统算**：

| 你填 | 系统算 |
|---|---|
| 触发日期、时限天数 | 到期日、剩余天数、预警灯 |

- **触发日期宁早勿晚**，认定存疑时取较早日期，留出安全余量
- **时限天数一律按日历日**填（如 `10`、`21`、`28`），不要按工作日折算
- **一个事件可能触发多条时效**：业主指示变更 → 先登记 `T1`（变更通知，10 日历日）；
  CN 发出后再登记 `T2`（PCO 提交，21 日历日，触发日为 CN 发出日）
- **已完成的记录不要删除**，把「实际完成日」填上、状态改为「已完成」即可——它是履约证据

### 13.5 附件 D（工期索赔跟踪台账）

- 类别代码用 `C1`–`C9`（见模板内说明）
- **「CN 时限到期日」「PCO 应交日」不用填**，系统按发现日/CN 发出日自动算
- 「当前状态」用规定取值：待发 CN／CN 已发待 PCO／PCO 已交待批／业主已批准／业主已驳回／滚动更新中／已关闭

## 14. 页面没数据？按这个顺序排查

| 现象 | 多半原因 | 怎么办 |
|---|---|---|
| 提示「没有在建状态的项目」 | 项目清单里没有状态为「在建」的项目 | 导入项目数据，或检查项目状态字段 |

## 15. 权限与使用范围说明

- 系统**单机运行**，不区分用户权限，谁打开谁就是管理员
- 数据存在本机 `opims.db`，**不会自动上传到任何服务器**
- 项目文件读写的是**云盘同步目录**，改动会随云盘同步到其他设备
- 「收文归档」是唯一会**移动/删除**云盘文件的功能，且每步可回滚

> 使用前请确认云盘处于正常同步状态。若云盘正在大量同步，建议等同步完成后再操作，
> 避免读到不完整的文件。
