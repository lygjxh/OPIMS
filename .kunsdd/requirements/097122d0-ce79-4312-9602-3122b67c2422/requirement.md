# opims - Oversea Project Integrated Management System

## 背景

海外运营中心以阿布扎比分公司为基础，为海外各机构的经营、生产、采购及风险防控提供全寿命周期的指导和支撑。作为公司海外业务的“大脑”和“指挥部”，是公司海外战略落地、市场拓展、项目履约和风险管控的责任主体。

战略统筹能力： 负责研究分析全球政治经济形势、行业发展趋势及区域市场特点，制定并滚动更新公司海外业务发展战略；统筹协调海外各机构业务发展，确保与公司总体战略保持一致。

市场开发能力： 统筹管理海外市场开发活动，建立和维护高层商务关系网络；牵头组织重大海外项目的信息追踪、投标报价及合同谈判；指导、支持各海外机构的属地化市场拓展。

资源整合能力： 整合公司内外、国内国外的优势资源（包括但不限于技术、人才、资金、设备、分包商、供应商等），为海外项目提供高效、优质的资源配置方案。

项目管控能力： 对海外项目执行全过程（从投标策划到竣工交付全寿命周期）进行指导、监督和支持，确保项目在进度、成本、质量、安全等方面满足合同要求和公司标准。

风险防控能力： 建立健全海外业务风险识别、评估、预警和应对机制，重点防控政治风险、法律合规风险、财税风险、汇率风险、安全风险等；指导海外机构制定应急预案并组织演练，保障海外人员、资产和业务安全。

作为海外运营中心项目管理部负责人，负责海外项目全过程的统筹协调与监控；组织项目开工策划、关键节点评审；协调解决项目执行中重大技术和资源问题。因此，我需要建立一套完善的项目信息系统，以便于随时更新、查看各项目的相关信息，并通过数据看板实时掌握项目进度、成本、风险和资源使用情况，为决策提供可视化支持。**该系统的核心建设思路包括：建立标准化的项目信息采集模板，打通海外各机构与总部之间的数据上报通道；构建多维度的数据分析模型，覆盖项目数量、进度、成本、风险、资源、分包、人员等关键管理域；搭建灵活的可视化看板，支撑不同层级管理者的决策需求。**

## 目标

建设一套覆盖海外项目全寿命周期的信息管理系统，实现以下具体目标：

- **信息标准化**：统一项目信息采集模板，确保各海外机构数据上报的规范性和一致性。
- **数据一体化**：打通总部与海外机构的数据通道，实现项目信息的实时汇聚与共享。
- **分析多维化**：构建涵盖进度、成本、风险、资源等多维度的数据分析模型。
- **决策可视化**：搭建灵活的数据看板，为不同层级管理者提供直观的决策支持。

系统暂时包括以下几个功能板块：

1. 首页看板
2. 项目清单
3. 项目进度
4. 项目质量
5. 项目分包
6. 项目人员
7. 分包商黑名单
8. 人员黑名单
9. 项目文件

暂定以上几个板块，后期根据情况再进行优化或增加板块。



## 功能要求

总体要求：

1. 系统基于WINDOWS，后续可能会需要同时支持鸿蒙系统
2. 系统仅需单机运行，可以单机部署 Web Server 通过浏览器访问，要求系统构建的简洁、美观，易于本地操作
3. 整个系统中以项目为基准，各板块数据联动，以项目简称作为关联键
4. 数据导入时，如果存在冲突，则提示冲突，并显示详细信息，并提供冲突处理选项（覆盖/跳过/保留两者）
5. 数据存储在本地 SQLite 数据库，支持手动备份（点击按钮选择保存路径，文件名 `opims_backup_YYYYMMDD_HHmm.db`）及恢复（选择备份文件，弹框确认覆盖后执行）
6. 不需要区分用户权限
7. 界面语言为中英双语可切换

板块要求：

1. 首页看板：
  1. 顶部数字卡片：项目总数 + 按状态（未开工/在建/停工/完工）的分项计数
  2. 世界地图：根据项目位置标记项目点，鼠标悬停显示项目简称；不同状态用不同颜色区分。位置数据优先级：GPS 坐标（如果有）&gt; 项目清单中的省/市/地址
  3. 底部快捷入口：9 个功能板块的卡片/按钮，点击跳转
2. 项目清单：
  1. 基础字段来源于公司项目管理情况汇总表（已解析，见待澄清 P0-2）。系统仅导入境外项目（境内/境外=境外）。
  2. 项目简称和合同编号通过与汇总表同文件夹的 `海外项目简称.xlsx` 映射文件获取（列序：序号/项目简称/合同编号/项目名称），按项目名称匹配。不修改原汇总表格式。
  3. 默认列表仅显示「在建」和「未开工」项目，在建排前；选择筛选条件后不受此限制。
  4. 额外支持可选字段：GPS 纬度、GPS 经度
  5. 支持导入 Excel（.xlsx），导出为 .xlsx（导出当前筛选结果），支持手动新建、修改、删除等
  6. 点击项目行弹出详情弹窗，分组卡片式显示所有字段（基础信息、地点日期、状态进度、业主/设计/监理、项目经理、技术负责人、质量/安全/费控经理、质量安全）
  7. 支持根据项目类型（EPC/PC/C）、项目状态（未开工/在建/停工/完工）、境内/境外、国别进行筛选，同时支持关键字搜索
  8. 项目简称唯一（与总体要求第3条一致，简称作为系统内关联键），编号也需唯一但仅作为业务标识
  9. 删除项目时，其他板块的关联数据保留并标记为「已删除项目」，不在界面上显示
3. 项目文件：
  1. 有设置根目录按钮，防止本机数据位置变动，可以手动调整整个系统项目文件的根目录
  2. 根目录下各文件夹名与项目清单板块中的项目简称一致，便于自动读取相关数据
  3. 项目文件夹下的文件夹暂定9个，分别为：
    1. 01.Contract
    2. 02.Sub-contract
    3. 03.Project Planning
    4. 04.Quality
    5. 05.Schedule
    6. 06.Report
    7. 07.Time Sheet
    8. 08.（预留）
    9. 09.Others
  4. 系统启动时使用上次保存的根目录路径和文件缓存，不自动全量扫描。提供手动刷新按钮，点击后扫描根目录及其子文件夹的当前文件状态并更新列表。系统需监控根目录的实时文件变动，在有新增、修改或删除文件时自动更新对应项目的文件列表。
  5. 启动时不做离线变更检测，以当前文件系统实际状态为准。
4. 分包商黑名单：
  1. 字段列表：分包商简称（必填）、分包商名称（必填）、国别、提报项目（关联项目简称）、列入原因、列入日期（必填）、限制日期、列入提报人、拉出原因、拉出日期、拉出提报人
  2. 数据联动：分包商名称和简称与「项目分包」板块的分包商数据关联；提报项目与「项目清单」板块的项目简称匹配
  3. 操作规则：
    - 支持新建、编辑、删除
    - 所有操作记录到操作日志（谁在什么时间做了什么）
    - 一旦执行「拉出」（填写拉出原因、拉出日期、拉出提报人），该条记录锁定——不可再修改、不可删除
  4. 筛选：支持按国别、提报项目、状态（列入中 / 已拉出）进行筛选
5. 人员黑名单：待后续补充。
6. 其他板块功能待后续补充。

### P0 — 阻塞开发

1. **技术栈选型**（已确认）：

  **Go 后端 + Vue 3 前端 + SQLite 数据库**，打包为单个 `opims.exe` 文件分发。
  
  | 层   | 选型                   | 关键理由                                         |
  | --- | -------------------- | -------------------------------------------- |
  | 后端  | Go                   | 编译为单个 .exe，用户双击即用；fsnotify 文件监控成熟稳定；可交叉编译到鸿蒙 |
  | 前端  | Vue 3 + Element Plus | 企业级 UI 组件开箱即用；vue-i18n 中英双语切换；静态文件嵌入 Go 二进制  |
  | 数据库 | SQLite（pure-Go）      | 单文件零配置，备份=复制文件，恢复=替换文件                       |
  | 打包  | 单个 .exe（\~20MB）      | 无需安装任何运行环境，双击启动后浏览器自动打开系统界面                  |
  

   不选 Python 的原因：PyInstaller 打包在 Windows 上不稳定（杀毒误报、中文路径、150MB+ 体积、每次改代码需重新打包），不适合非技术人员使用。

   鸿蒙兼容：Go 可交叉编译到 ARM64 OpenHarmony，前端代码无需改动。

5. **筛选维度的值域**（已确认）：
  - 项目类型：EPC / PC / C
  - 项目状态：未开工 / 在建 / 停工 / 完工（来自汇总表 4 个 sheet）

6. **导入导出格式**（已确认）：导入格式为 Excel .xlsx；导出格式同为 .xlsx，导出范围为当前筛选结果（用户看到什么导出什么）。
7. **数据库备份恢复机制**（已确认）：
  - 触发方式：手动——点击「备份」按钮，弹出保存位置选择框，生成备份文件
  - 备份文件命名：`opims_backup_YYYYMMDD_HHmm.db`（如 `opims_backup_20260615_1730.db`）
  - 恢复：选择备份文件后弹框确认「恢复将覆盖现有数据，确认继续？」，确认后执行替换
