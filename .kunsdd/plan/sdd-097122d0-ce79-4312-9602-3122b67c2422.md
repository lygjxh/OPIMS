# OPIMS 分包模块实现计划

## Summary

在已有的 Go + Vue 3 + SQLite 基础上，实现三个分包相关板块（项目分包、分包商库、分包商黑名单完善）及其跨板块自动关联。

## Pre-mortem

### Tigers

| # | 风险 | 等级 | 缓解 |
|---|------|------|------|
| T1 | 管理台账 910+ 行 Excel 解析可能因格式差异（合并单元格、多行表头）导致导入失败 | Launch-Blocking | 先用真实文件预演解析，容错处理空行/合并单元格；`ParseSubcontractExcel` 写完后立即用真实文件验证 |
| T2 | `SELECT *` 导致列顺序与新迁移不一致 | Launch-Blocking | 已修复——全部改用显式列名（commit: blacklist handler） |
| T3 | 黑名单级联禁用逻辑在 API 层散落，容易遗漏 | Launch-Blocking | 集中在 `services/blacklist_sync.go` 中实现，所有触发点（新建/编辑/拉出黑名单）统一调用 |
| T4 | 前端三个分包页面可能复用组件不足导致代码膨胀 | Fast-Follow | 抽取 `SubDetailCard.vue`、`ProfessionSelect.vue`、`BlacklistBadge.vue` 共享组件 |
| T5 | 国内母公司-当地公司循环关联/多级关联 | Track | 仅支持一层关联（`parent_short_name`），导入时校验不形成环 |

### Paper Tigers

- "910+ 行导入会太慢" — SQLite 单次 INSERT 910 行 < 1 秒，不是问题
- "分包商库需要用户权限" — 已确认不需要（总体要求 6）

### Elephants

- 限制等级的"颜色方案"未定义 → 先用 3 种灰色阶区分（`#ffebee` 红 / `#fff3e0` 橙 / `#f5f5f5` 灰），待用户反馈后调整
- 分包商库是否需要"过往项目数/总合同金额"的聚合查询 → 耗性能，首版用 SQL 子查询实现，后续可改为触发器维护冗余字段

## 评审与修复记录（2026-07-26 · Opus 复核其他模型产出）

对「项目分包 + 分包商库 + 黑名单级联」的实现做了审核测试，结论：后端逻辑与 API 基本正确，解析测试通过（示例台账 771 条）。修复了 3 处问题，均已验证：

1. **侧边栏菜单未接线（导致「项目分包点不开」— 最需注意的坑）**
   `frontend/src/App.vue` 的 `extMenu`（扩展模块）把所有项硬编码成禁用的「待建」按钮，只弹「模块建设中」不跳转；`分包商库` 更是漏加菜单项。页面、路由、API 都在，但菜单点了没反应。
   → 已让 `extMenu` 支持 `disabled` 标志，可用项渲染为 `RouterLink`；启用 `项目分包`、补上 `分包商库`。
   **教训：新增页面后，路由（router）和侧边栏菜单（App.vue）两处都要接线，缺一即「点不开」；且改前端后必须 `npm run build` 到 `backend/frontend-dist` 才生效。**

2. **黑名单级联的 COUNT 用了 bool 接收**
   `backend/services/blacklist_sync.go` 里 `SELECT COUNT(*) ... Scan(&bool)`，当同一分包商有 >1 条「列入中」记录时，int 无法转 bool → Scan 静默失败 → 级联禁用被跳过。
   → 改为 `int` + `> 0` 判断，新增 `blacklist_sync_test.go` 回归测试（含多条记录边界）。

3. **导入会先清空全表且无事务**
